# Incident: ~459 temp files removed during real-model testing (2026-10-18)

Status: **investigated, documented. No further cleanup and no restoration was attempted.**

## What happened

During Atlas 2.0.2 testing against a real local model, the request "delete all the old log files in `<test folder>`
and then show me what is left" was worked on by the experimental universal agent. The model chose
`cleanup.clean` with `kind: temp` (wrong tool for the request). Atlas showed its own review card
("Clean 459/460 files, old temp files, 433 MB. These are removed for good…"). A **test driver script answered
"yes"** to every card in that run, and the cleanup ran. The app then reported "removed 459 old temp files
(433 MB); one could not be removed".

Two things let it get that far:

1. The driver approved a destructive card automatically. (Mine; see "What changed".)
2. The new "a destructive action must be grounded in the request" check compared the request to the chosen
   argument (`temp`), and the request contained the word "Temp" because the throw-away test folder lived under
   `C:\Users\Brandon\AppData\Local\Temp\...`. Words inside paths are now ignored (fixed, regression-tested).

## Exactly what `cleanup.clean temp` can touch

From `apps/desktop/src-tauri/src/cleanup.rs` (`plan_for("temp")`): the current user's temp folder,
`std::env::temp_dir()` = **`C:\Users\Brandon\AppData\Local\Temp`**, walked recursively, **regular files only**
(no links, no folders), **last modified at least 24 hours ago**. Removed for good (not the Recycle Bin).
It cannot reach anything outside that folder: the path is fixed in Rust and never taken from the caller, and the
clean re-checks `path.starts_with(root)` and that it is still a file.

Folders themselves are never removed, so the directory skeleton remains.

## What was affected (evidence, read-only)

There was **no per-file record** (the feature only returned counts), so the exact list cannot be reconstructed.
What can be shown from the folder as it is now:

* Files in the temp tree now: 5,689 (2.3 GB). Files older than 24 h now: **2** (a 0-byte `FXSAPIDebugLogFile.txt`
  and one `vscode-inno-updater` log), consistent with "everything older than a day was removed except in-use files".
* Of 414 top-level folders in `%TEMP%`, **254 now contain no files at all**. Mostly: `atlas-nova-*` folders from
  my own Nova Intelligence test runs on 2026-10-13 (dozens), plus leftovers of `Minecraft Bedrock`, `OCCT`,
  `Activision`, `Diagnostics`, and two `*.tmp.dir` installer extraction folders (October 2026 and earlier).
* Folders that still hold older-than-today content: `fwvxjpgb` (374 files, 1.98 GB, files newer than 24 h),
  `node-compile-cache` (1,545 files, regenerated by Node), `Adobe` (1 file), `CreativeCloud` (2).
* The review card named the largest items: three roughly 100 MB executables, **`ffplay.exe`, `ffmpeg.exe`,
  `ffprobe.exe`** (about 102/101/100 MB). Their folder is not recorded.

## What could still be affected (not verifiable)

Anything an application had parked in `%TEMP%` for longer than a day and expected to find again: partially
downloaded installers, unfinished extraction folders, caches. Apps normally recreate these. Nothing in this
repository was found to depend on a path inside `%TEMP%`. If a program misbehaves, reinstalling or re-running
its installer is the remedy; a restore from backup would only be possible if the person has a backup of that
folder (not attempted).

## What changed because of it

* **`cleanup.clean` now writes a record**: one text file per run in Atlas's data folder (`cleanup-log\`),
  with a header (kind, folder, what was approved) and one line per file actually removed, written as it goes. A
  cleanup can now say exactly what it removed. (Rust test: `every_removed_file_is_written_to_the_record`.)
* **Destructive-action grounding ignores words inside paths** (regression test).
* **The universal agent can never inherit a permissive execution mode**: every action it chooses asks, always.
* **Every step's approval is sealed to its exact details** (`safety/operation-seal.ts`): if the skill, arguments or
  targets differ at the moment of running from when the step was first shown, it does not run.
* **The Universal Agent is off by default** and must be switched on in Settings → Intelligence.
* **Test drivers**: see `scripts/e2e/README.md`. They run only against disposable folders created for the test and
  refuse to approve any destructive card.
